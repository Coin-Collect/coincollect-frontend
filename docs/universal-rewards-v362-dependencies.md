# V3.6.2 dependency risk register

The same Yarn audit collected 38 distinct high advisories before the release changes and 35 afterward. The [advisory register](universal-rewards-v362-advisories.json) records every originally observed high advisory with its dependency roots, relevance and disposition. The gate still fails on a critical advisory or an unreviewed production high. Removed exceptions must stay absent from the audit.

| Finding | V3.6.2 disposition |
| --- | --- |
| WalletConnect query parsing | Upstream decode-uri-component 0.5.1 fixes the URL decoding issue. The exact licensed upstream implementation is [converted to CommonJS](../vendor/decode-uri-component/README.md) for query-string 7.1.3 and pinned to that consumer. The CI compatibility check parses and round-trips regular WalletConnect URI data using the installed resolver. The historical exposure required attacker-influenced encoded input to reach client URL decoding. |
| Picomatch through WalletConnect Node storage and Jest | The 2.3.2 patch stays within the declared 2.x ranges of anymatch, readdirp and jest-util. The wallet paths were transitive filesystem glob consumers and required untrusted patterns or matching data to reach those Node paths. |
| Snapshot lodash.set | The SDK's only CoinCollect call site retrieved public vote scores through HTTP. That endpoint, strategy order, payload and score arithmetic remain in use through the narrow checked client. Removing the SDK removes the unused callable object-path setter. The original upstream vulnerability requires attacker-controlled path segments to reach the setter. |
| Web3Modal Wallet and Zod | The retained Web3Modal v5 wallet component declares Zod v3. The published fix begins at Zod 4.6.6. A major override would change the SDK's supported API contract. Inspecting the wallet frame bindings found schema parsing, but the relevant exposure requires untrusted frame messages to reach an applicable constrained collection schema. App and remote-origin restrictions are relevant controls, with live hosted frame and SDK behavior remaining an independent review obligation. Production WalletConnect and hosted frame sign-off stay open. |

The remaining 34 high advisory IDs affect development and test dependencies in this snapshot. Their risk requires use of the affected tooling with untrusted inputs, archive distributions, configuration, or local dev-only HTTP traffic. Keep release builds on reviewed sources, frozen lockfiles and trusted CI runners. The release gate uploads full registry output so tooling findings remain visible. Future SDK upgrades require real extension and applicable WalletConnect session checks rather than a resolver override.
