# Contract Manager

Open `/contract-manager` from More, or `/admin/contract-manager` from the existing admin panel. The public route supports inspection before a wallet connects. The admin route uses the regular factory-owner gate. The wallet must be connected to Polygon for production withdrawals. In local fork mode the tool stays on the loopback fork and skips external ABI lookup.

Enter a contract address to check native POL, tracked CoinCollect tokens, token addresses exposed by supported contract getters, or up to five manually entered ERC-20 addresses. This is a list of checked assets. It does not enumerate every token on the chain. The page also shows readable ownership, declared roles for the connected wallet, and exact function signatures when the ABI is available.

The withdrawal flow reads the amount for the connected wallet, previews the recipient and fee, rechecks the same withdrawal immediately before the wallet prompt and tracks the transaction receipt. The user signs in their wallet. The displayed maximum network fee allows up to 20% headroom on the initial gas quote, limited by the wallet's POL balance. The wallet receives the fresh gas quote. A change in wallet, amount, calldata or recipient, or a fresh fee above the displayed maximum, requires a new preview.

On Polygon mainnet, EIP-1559 quotes use the RPC's suggested priority fee with a 25 Gwei floor. The wallet returning a transaction hash starts receipt tracking. If the Polygon RPC cannot find the hash, Check status reports that separately and keeps the withdrawal locked while the previous attempt is unresolved.

| Reviewed runtime                                                                     | Enabled withdrawal                                                                                                                                                                                  |
| ------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Reviewed NFT implementations, including CoinCollect Starter, Bronze, Silver and Gold | Native `withdraw()` to the current owner. A fresh simulation trace must prove one transfer of the full POL balance to that wallet.                                                                  |
| Standalone Ownable Receipts fixture                                                  | Native `withdrawFunds()` to the current owner, for the matching runtime only.                                                                                                                       |
| Standalone OpenZeppelin PaymentSplitter 4.9.6                                        | Native `release(address)` or `release(address,address)` for the reviewed Polygon WPOL token. The recipient is the connected payee, and the amount comes from the corresponding `releasable` getter. |

NFT withdrawal support follows the reviewed deployed code. A new deployment can use its own address and owner. Seven reviewed builds cover the twelve Polygon collections configured in CoinCollect. For those builds, only the IPFS digest in the expected Solidity metadata footer is masked before hashing. The executable bytes, compiler version and footer structure must match. The connected wallet must still match `owner()`, and the transfer is simulated again before asking for wallet confirmation.

Ownable Receipts and PaymentSplitter use full runtime hashes. For Ownable Receipts use the checked-in fixture and solc 0.8.30, Paris, optimizer on with 200 runs, `metadata.bytecodeHash: none`. For PaymentSplitter use the unmodified source tree at the OpenZeppelin v4.9.6 tag, with imports rooted at `contracts/`, solc 0.8.30, Paris or Cancun, optimizer off or on with 200 runs, and the same metadata setting. No deployed template or new service is required by the frontend.

An ABI from [Sourcify](https://docs.sourcify.dev/docs/api/) is accepted for inspection when its deployed bytecode matches the connected chain's bytecode. CoinCollect's existing ABIs can also be shown as project references. ABI names, selectors and ownership alone never activate writes. Unreviewed bytecode, upgradeable variants, reviewed methods with unrecognized arguments or tokens, and missing simulation evidence stay read-only.
